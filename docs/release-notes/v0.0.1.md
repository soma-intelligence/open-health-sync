# Open Health Sync v0.0.1

The first public release of Open Health Sync, a self-hostable health data aggregator. It
collects data from Apple Health and Withings, keeps every raw payload, normalizes it into one
canonical model with one set of units, and serves it over a REST API and a read-only MCP
server. One Go binary plus Postgres with TimescaleDB.

**This is an early preview.** APIs, configuration and the database schema may change in any
0.x release. Pin the version you run and read the [changelog](https://github.com/soma-intelligence/open-health-sync/blob/v0.0.1/CHANGELOG.md) before you upgrade.

## Install

Container image (`linux/amd64`, `linux/arm64`):

```sh
docker pull ghcr.io/soma-intelligence/open-health-sync:0.0.1
```

The image is tagged `0.0.1` and `edge` (the newest final release, never a pre-release such as `0.1.0-rc.1`). There is no `latest` tag while the
version is 0.x: pin a version. The compose file in `deploy/` runs this image; see
[self-hosting](https://github.com/soma-intelligence/open-health-sync/blob/v0.0.1/docs/self-hosting.md).

Binaries for Linux and macOS on amd64 and arm64 are attached below, with `checksums.txt`
(SHA-256). Check a download with `sha256sum -c checksums.txt --ignore-missing`.

## What works

- **Apple Health.** An iOS app (yours; no SDK ships yet) uploads HealthKit data as gzip NDJSON
  parts; quantities, categories, sleep, workouts with routes and nutrition land in the canonical
  model, and ECG and heartbeat series are stored.
- **Withings.** Bring your own Withings developer app. Users connect over OAuth;
  measurements, activity, sleep, workouts and ECG are pulled on a schedule and on push
  notifications.
- **One model, one set of units.** Deduplication, source and device attribution, validation,
  and daily summaries per local day.
- **Raw payloads as the source of truth**, in a local folder or any S3 compatible store.
- **Multi-tenant API** with tenant keys and scoped user tokens, described by
  `api/openapi.yaml`.
- **Read-only MCP server** so an AI agent can read a user's data.
- **Hard deletion** of a user's raw files and rows on request.
- **Crash-safe pipeline** with retries, parking, an orphan scanner and a drainer.
- **Runs small.** A Raspberry Pi 5 with 4 GB runs the full stack.

## Known limitations

- **Crash recovery takes 10 minutes.** After a hard kill (`kill -9`, power loss), a job that
  was in flight is claimed again only after its 10 minute visibility timeout.
- **Single region.** One database and one raw store per instance; no multi-region replication.
- **Not yet available:** FHIR import or export, outbound webhooks, mobile SDKs.
- **ECG and heartbeat series are stored but not served yet.** No REST route or MCP tool reads
  them in this release.
- **`/metrics` is unauthenticated.** It exposes instance wide counters only, but block it at
  your reverse proxy or set `OHS_METRICS=false`.

The [operating notes](https://github.com/soma-intelligence/open-health-sync/blob/v0.0.1/docs/self-hosting.md#operating-notes) list the rest of what an operator
should plan around.

## Roadmap

- More connectors for wearables and health platforms.
- More outputs: standard formats such as FHIR, and webhooks when new data lands.
- Client SDKs for mobile apps and servers.

Ideas and connector requests are welcome as GitHub issues.
