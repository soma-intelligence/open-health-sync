# Open Health Sync v0.3.0

A reliability release. Each provider is now pulled on its own schedule, deleted and edited
HealthKit samples leave the server, and a stress and fuzz pass fixed how `ohs` behaves under
load, during database outages and on bad input. Many more figures are validated before they are
stored. Still an early preview: APIs, configuration and schema may change in any 0.x release, so
pin the version you run.

## Install

Container image (`linux/amd64`, `linux/arm64`):

```sh
docker pull ghcr.io/soma-intelligence/open-health-sync:0.3.0
```

The image is tagged `0.3.0` and `edge`. There is no `latest` tag while the version is 0.x.
Binaries for Linux and macOS on amd64 and arm64 and the Android example app
(`ohs-example-android.apk`) are attached below, with `checksums.txt` (SHA-256). The image and
`checksums.txt` are signed with Sigstore cosign, keyless; the commands to check both are in
[SECURITY.md](https://github.com/soma-intelligence/open-health-sync/blob/v0.3.0/SECURITY.md#verifying-releases).

The [quickstart](https://github.com/soma-intelligence/open-health-sync/blob/v0.3.0/README.md#quickstart)
runs it with Docker Compose, [Render, Fly.io or Railway](https://github.com/soma-intelligence/open-health-sync/blob/v0.3.0/docs/deploy-platforms.md)
host it for you, and the [Helm chart](https://github.com/soma-intelligence/open-health-sync/blob/v0.3.0/docs/helm.md)
(chart 0.3.0) runs it on Kubernetes.

## What's new

### Sync

- **A sync policy per provider.** Each connector declares how often it is pulled with and
  without notifications, how far each pull reads again for late or revised data, how far a new
  connection is backfilled, and an optional daily reconciliation. Dexcom re-reads 6 hours (its
  readings reach the API up to 3 hours late outside the US), OMRON 72 hours, Ultrahuman 48;
  Oura, WHOOP, Withings and Dexcom are backfilled over 90 days, Polar and Suunto over the 28 days
  their APIs keep. The table is in
  [background sync](https://github.com/soma-intelligence/open-health-sync/blob/v0.3.0/docs/background-sync.md#sync-policy-per-provider).
- **A failed pull window is fetched again.** The regular pull reaches back to the end of the last
  complete pull instead of the last successful job.

### Apple Health

- **Deleted and edited HealthKit samples are removed from the server.** HealthKit edits a sample
  by deleting it and saving a new one, so every edited weight or blood pressure used to stay
  twice. The Swift SDK now uploads deletion lines, and a sample is removed only once no other
  copy stands for it (migration `0043`).
  [Deletions](https://github.com/soma-intelligence/open-health-sync/blob/v0.3.0/docs/connectors/apple-health.md#deletions)
- **US units in export.xml**: heights in feet, masses in ounces, lengths in inches, speeds in ft/s
  and volumes in fluid ounces are converted instead of refused.

### Running under load and outages

- **Memory**: the compose file caps `ohs` at 1 GB and `ohs` sets `GOMEMLIMIT` to three quarters of
  the container limit. [Memory profiles](https://github.com/soma-intelligence/open-health-sync/blob/v0.3.0/docs/self-hosting.md#memory),
  the Raspberry Pi one included.
- **Uploads**: one tenant can no longer hold every ingest slot, and an uploaded part may expand to
  64 MiB once decompressed (`OHS_INGEST_MAX_DECOMPRESSED_MIB`, up to 512).
- **Outages answer 503 with `Retry-After`**, not 500: a database restarting, out of connections or
  not answering, and a full or read-only raw store. A frozen database no longer holds requests
  for minutes, and jobs in flight during a Postgres restart are retried after their usual
  backoff instead of a 10 minute wait.
- **Slow clients**: a request must be read within 2 minutes (uploads keep 5), and
  `OHS_MAX_CONNECTIONS` (default 4096) caps open connections.

### Data quality

- Sleep phases, ECG recordings, daily summaries, observations and workout figures are now
  range-checked, and every record kind refuses a time before 1990. One bad figure no longer
  costs the whole record: it is dropped and listed under `quality_dropped` in the record's
  metadata.
- NaN and infinite values, NUL characters and invalid UTF-8 are refused or cleaned instead of
  stored or answered with a 500.
- New connector fuzz tests found and fixed overflowing durations, zero times and unit conversions
  in a dozen connectors.

### Also new

- `deploy/Caddyfile`: Caddy with automatic TLS in front of the compose stack.
- A synthetic data generator for every documented provider, run nightly through a live server.
- `internal/quality`: a first data quality score library with its backtest report. No API uses it
  yet. [docs/quality.md](https://github.com/soma-intelligence/open-health-sync/blob/v0.3.0/docs/quality.md)

The full list is in the [changelog](https://github.com/soma-intelligence/open-health-sync/blob/v0.3.0/CHANGELOG.md#030---2026-10-28).

## Upgrade notes

Take a backup first, then set `OHS_VERSION=0.3.0` in your `.env`, pull and recreate (the
[self-hosting guide](https://github.com/soma-intelligence/open-health-sync/blob/v0.3.0/docs/self-hosting.md#upgrading)
has the full steps). Migration `0043` applies on start and is quick. A v0.2.0 configuration starts
as is, with these changes in behavior:

- **The compose file caps `ohs` at 1 GB.** Raise `OHS_MEM_LIMIT` if your instance needs more.
- **Garmin notifications are refused while `OHS_GARMIN_INBOUND_TOKEN` is unset.** Set it and add
  `?token=<value>` to the notification URLs in Garmin's portal, or only the scheduled pulls bring
  data.
- **An uploaded part may expand to 64 MiB** instead of 512. The SDKs and `ohs import` send parts of
  at most 8 MiB, so they are not affected.
- **Outages answer 503** where they answered 500. Clients that retry 503 keep their uploads.
- **Values that used to pass and are now refused**: an oxygen saturation under 50 %, a body fat
  percentage under 2 % or over 80 %, negative nutrition figures, times before 1990.
- **Rows stored earlier keep their values.** To make Apple Health rows stored by 0.2.0 deletable,
  upload the history again (`resetAnchor` in the Swift SDK). Fitbit points relayed from Apple Health
  keep their old type and source until you run
  [the relayed points script](https://github.com/soma-intelligence/open-health-sync/blob/v0.3.0/docs/how-to/fitbit-relayed-points.md).

## Known limitations

- Fitbit needs a Google Health API project, and Google is not onboarding new ones yet. Garmin
  keys go to approved businesses only. Most other cloud sources need a developer or partner app
  of your own with the provider; each connector guide says which.
- Eight Sleep uses the sign-in of the Eight Sleep app, not a public API, so it can break when the
  app changes.
- Apple Health deletions do not cover sleep stages, ECG and heartbeat series yet.
- FHIR R4 has no bulk export (`$export`) yet.

## Security

Report vulnerabilities privately through
[GitHub Private Vulnerability Reporting](https://github.com/soma-intelligence/open-health-sync/security/advisories/new).
See [SECURITY.md](https://github.com/soma-intelligence/open-health-sync/blob/v0.3.0/SECURITY.md).
This release refuses more reserved addresses as webhook destinations (NAT64, 6to4 and the
reserved IPv4 ranges) and applies a refused consent category to the figures of sleep sessions,
workouts and daily summaries too. Upgrading is recommended.
