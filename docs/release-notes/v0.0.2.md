# Open Health Sync v0.0.2

A usability release for people who run and integrate Open Health Sync. No change to the data
model or the database schema. Everything in the [v0.0.1 release notes](https://github.com/soma-intelligence/open-health-sync/blob/v0.0.1/docs/release-notes/v0.0.1.md)
about the early preview still applies: APIs, configuration and schema may change in any 0.x
release, so pin the version you run.

## Install

Container image (`linux/amd64`, `linux/arm64`):

```sh
docker pull ghcr.io/soma-intelligence/open-health-sync:0.0.2
```

The image is tagged `0.0.2` and `edge`. There is no `latest` tag while the version is 0.x.
Binaries for Linux and macOS on amd64 and arm64 are attached below, with `checksums.txt`
(SHA-256).

## What changed

- **Help in the binary.** `ohs help`, `ohs help <command>`, `-h` and `--help` on every command,
  and `ohs --version`. A command line error exits 2.
- **Clearer errors.** A refused `ohs mcp` handshake says whether the key, the scope or the URL
  is wrong. A 403 names the credential the endpoint takes. A wrong method on a known path
  answers 405 with an `Allow` header instead of 404. Database, port and raw store failures name
  the variable to check.
- **Raw store check at start.** `ohs serve` and `ohs doctor` write and delete a probe object, so
  an unwritable volume stops the start with a hint instead of failing every upload.
- **Request ids.** Every API response carries `X-Request-Id`, repeated in problem bodies and on
  the log lines about the request.
- **`GET /openapi.yaml`** serves the description of the running version, for Postman, Swagger
  UI or Redoc.
- **Key rotation without SQL.** `ohs admin tenant list`, `ohs admin key create`, `key list` and
  `key revoke`.
- **Logs** write durations as text (`24h0m0s`), and the start line names the version.
- **MCP.** Server instructions steer agents to `get_daily` for trends. The image carries the
  `io.modelcontextprotocol.server.name` label and the repository has a `server.json` for the
  official MCP registry.
- **Docs.** A providers page with supported and planned sources, upgrade, backup, restore and
  secret rotation in the self-hosting guide, Claude Desktop and Claude Code setup in the MCP
  guide, and a README with real screenshots.

## Upgrade notes

Set `OHS_VERSION=0.0.2` in your `.env`, then pull and recreate (the
[self-hosting guide](https://github.com/soma-intelligence/open-health-sync/blob/v0.0.2/docs/self-hosting.md)
has the full steps, including a backup first). Migrations apply on start as before.

Two settings are now validated when the process starts, so a configuration that 0.0.1
accepted can be refused. Check them before you upgrade:

- **`OHS_PUBLIC_URL`** must be an absolute `http` or `https` URL with no query and no fragment.
  `localhost:8080` (no scheme) and `https://example.com/?x=1` are refused. Before, a bad value
  only broke OAuth callbacks later.
- **`OHS_LOG_LEVEL`** must be a known level. An unknown value is refused instead of being
  ignored.

`ohs migrate` and `ohs admin` do not read these two settings, so they keep working while you fix
the file. `ohs doctor` reports both.

Also new at start: the raw store must accept writes. If the container user cannot write the
raw folder or bucket, `ohs serve` stops and prints the fix (typically a `chown` of the volume
to uid 65532).

Log lines now show durations as text rather than nanoseconds. If you parse them, update the
parser.

## Known limitations

Unchanged from v0.0.1: crash recovery takes 10 minutes, one region per instance, no FHIR or
webhooks or SDKs yet, ECG and heartbeat series are stored but not served, `/metrics` is
unauthenticated, and the Withings steps are not verified with a real account.
