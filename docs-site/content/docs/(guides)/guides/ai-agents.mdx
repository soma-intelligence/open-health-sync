Open Health Sync speaks the [Model Context Protocol](https://modelcontextprotocol.io). An agent
can list and read a person's samples, sleep, workouts, daily summaries and coverage. It cannot
write, delete or connect anything.

<Steps>
<Step>

### Mint a read-only token

A token whose only scope is `read` may live up to 30 days, so a person can keep it in their agent
configuration:

```sh
curl -s -X POST $OHS/v1/users/$USER_ID/tokens -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' -d '{"scopes":["read"],"ttl_seconds":2592000}'
# {"token": "ohs_ut_...", "expires_at": "...", "scopes": ["read"]}
```

The token sees that one user only. It stops working at `expires_at` or when the user is deleted.

</Step>
<Step>

### Add the server to your agent

<Tabs items={['Claude Desktop', 'Claude Code', 'Remote (URL)', 'Docker']}>
<Tab value="Claude Desktop">

In Claude Desktop, open Settings, Developer, Edit Config, and add to
`claude_desktop_config.json`, then restart:

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "open-health-sync": {
      "command": "/usr/local/bin/ohs",
      "args": ["mcp"],
      "env": {
        "OHS_MCP_URL": "https://ohs.example.org",
        "OHS_MCP_KEY": "ohs_ut_..."
      }
    }
  }
}
```

`ohs mcp` holds no data and needs no database: it forwards every message to the `/mcp` endpoint
of the instance. Get the binary from the
[releases](https://github.com/soma-intelligence/open-health-sync/releases).

</Tab>
<Tab value="Claude Code">

With the `ohs` binary:

```sh
claude mcp add open-health-sync -e OHS_MCP_URL=https://ohs.example.org \
  -e OHS_MCP_KEY=ohs_ut_... -- ohs mcp
```

Or straight to the remote endpoint, without the binary:

```sh
claude mcp add --transport http open-health-sync https://ohs.example.org/mcp \
  --header "Authorization: Bearer ohs_ut_..."
```

</Tab>
<Tab value="Remote (URL)">

Agents that speak Streamable HTTP connect to the instance directly:

```json
{
  "mcpServers": {
    "open-health-sync": {
      "type": "http",
      "url": "https://ohs.example.org/mcp",
      "headers": { "Authorization": "Bearer ohs_ut_..." }
    }
  }
}
```

The endpoint is stateless and answers plain JSON, so it works behind any reverse proxy.

</Tab>
<Tab value="Docker">

Without the binary, the image does the same. `-i` keeps stdin open; inside the container
`localhost` is the container, so give the instance's real address, and pin the image tag of
your instance's release:

```json
{
  "mcpServers": {
    "open-health-sync": {
      "command": "docker",
      "args": ["run", "--rm", "-i", "-e", "OHS_MCP_URL", "-e", "OHS_MCP_KEY",
               "ghcr.io/soma-intelligence/open-health-sync:<version>", "mcp"],
      "env": { "OHS_MCP_URL": "https://ohs.example.org", "OHS_MCP_KEY": "ohs_ut_..." }
    }
  }
}
```

</Tab>
</Tabs>

</Step>

### Ask

> How did my resting heart rate move over the last month, and on which days did I sleep less
> than six hours?

The server's instructions steer agents to daily summaries for trends and to narrow windows for
raw samples, so answers stay small.

## Good to know

- `OHS_MCP_URL` must be `https` unless the host is loopback, and redirects are not followed: give
  the final URL.
- A 401 means a wrong key or an expired token; a 403 a user token without the `read` scope; a 404
  or 405 a URL that is not the instance's base URL.
- Records carry strings written by devices and providers (source names, metadata, meal labels).
  Agents must treat them as data, never as instructions.
- A tenant key works too, and sees every user of the tenant. Prefer a user token for a person's
  own agent.

Every tool and argument: [MCP server reference](/docs/api-reference/mcp).
